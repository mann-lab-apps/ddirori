# 띠로리 스코어 유입 개선 백로그

최종 갱신: 2026-11-12. 악보앱의 다운로드를 늘리기 위해 가장 쉬운 유입 개선부터 한 가지씩 시도한다.

## 목표와 운영 방식

- 핵심 지표: App Store Connect 최초 다운로드 **3 → 5건**.
- 보조 마일스톤: App Store Connect 노출 **32 → 100회**. 기존 화면의 기간 길이와 국가 필터를 확인하고 같은 조건으로 비교한다.
- 웹 방문과 검색 노출은 원인을 파악하는 참고 지표다. App Store 노출과 합산하지 않는다.
- 한 번에 개선 하나만 실행한다. 변경일과 비교 기간을 기록하고 결과를 본 뒤 다음 항목을 고른다.
- 스토어 노출 100회 미만이면 노출 확대가 충분히 실행됐는지부터 본다. 100회 이상에서 다운로드 5건 이상이면 같은 방법을 한 번 더 시도하고, 미달이면 유입 경로와 스토어 소개를 점검해 다음 개선 하나를 고른다. 작은 표본이므로 한 번의 달성으로 효과를 확정하지 않는다.
- 수집되지 않은 데이터는 0으로 처리하지 않는다. 본인·설정 테스트 접속은 구분해서 본다.

## 현재 진행 상황

| 작업 | 상태와 근거 |
|---|---|
| 공식 웹·GA 연결 | 완료. `ddirori.com` 배포 및 GA 콘솔 수집 확인 |
| Google 검색 등록 | 사용자 등록 완료 확인. `/score/` 실제 URL 테스트 통과, 실제 색인·검색 유입은 관찰 |
| Naver 검색 등록 | 사이트 목록 추가와 홈페이지 소유확인 태그 배포 확인. 소유확인·사이트맵·수집 요청의 최종 처리 결과는 콘솔에서 확인 |

등록 대상은 `https://ddirori.com`, 사이트맵은 `https://ddirori.com/sitemap.xml`, 우선 관찰할 페이지는 `https://ddirori.com/score/`다.

## 다음 작업

우선순위는 실행 순서의 후보이며 전체를 한꺼번에 적용하지 않는다. 소요 시간은 작업 예상치다.

| ID | 우선순위 | 작업 | 시작 조건과 최소 실행 | 완료 기준 |
|---|---|---|---|---|
| O1 | 먼저 관찰 | 검색 등록 결과 확인 | Google URL 검사와 Naver 요청 결과를 확인. 수집 오류가 있으면 그 오류 하나부터 해결 | 색인·수집 상태와 확인일 기록. 정상 요청은 매일 반복 제출하지 않음 |
| G1 | 다음 후보 | 기존 SNS·블로그 프로필에 소개 링크 추가 | 이미 운영 중인 채널 하나가 있으면 실행. 약 5분. 없으면 보류 | `/score/` 링크 하나 게시, 게시일과 채널 기록. `utm_source`, `utm_medium`, `utm_campaign`으로 구분 |
| G2 | 대기 | 웹 검색 제목 개선 | 색인 후 관련 검색 노출이 약하거나 노출 대비 클릭이 약할 때. 약 15분 | 제목 하나 수정·배포 후 검색어·노출·클릭 변화 관찰. 후보: `무료 PDF 악보 뷰어 · 필기와 연습 | 띠로리 스코어`. 공개 앱의 실제 기능·가격 확인 후 확정 |
| G3 | 대기 | PDF 악보 사용자 채널 한 곳에 사용 장면 소개 | 기존 링크만으로 유입이 약할 때. 스크린샷 2장과 짧은 설명부터, 약 30분. 영상은 필요할 때 추가 | 실제 악보 열기·필기·연습 흐름을 보여주는 글 1건과 추적 링크. 허용된 채널에서 직접 게시하고 게시일 기록 |
| S1 | 대기 | 짧은 질문과 답변 보완 | 검색어·사용자 질문에서 정보 부족이 보일 때. 일반 SEO와 AI 검색 공통 | 무료 여부·지원 기기·PDF 가져오기 등 실제 질문 하나에 답하는 본문 추가. 기존 설명과 공개 기능을 먼저 확인 |
| S2 | 후순위 | 앱 구조화 데이터 검토 | 제목·핵심 설명이 정리된 뒤 검토 | 본문과 일치하는 앱 이름·운영체제·가격·스토어 주소를 `SoftwareApplication` 등에 반영하고 검증. 검색 특수 표시나 순위 상승을 완료 기준으로 삼지 않음 |
| S3 | 후순위 | 문제 해결 가이드 한 편 작성 | 실제 검색어가 생겼지만 소개 페이지로 답하기 어려울 때 | 예: iPad에 PDF 악보 가져오기. 실제 앱 화면으로 설명하고 소개 페이지로 연결. 대량 글 생성은 하지 않음 |
| A1 | 후순위 | AI 검색 접근성과 유입 확인 | 기본 색인·본문 정리 이후 | 대상 AI 검색 서비스의 공식 크롤러 정책을 확인해 의도치 않은 차단만 점검. 식별 가능한 추천 유입이 있으면 GA에서 관찰. AI 답변 노출을 위한 별도 도구 구매는 보류 |

G1·G2·G3가 2026-11-11에 나열했던 나머지 세 작업이다. G2는 SEO 항목과 중복되므로 별도 작업으로 늘리지 않는다. 현재 다음 실행 후보는 **기존 채널 하나의 프로필 링크 추가**다.

## SEO와 AI 검색 적용 원칙

Google의 AI Overviews·AI Mode는 일반 SEO 기본 원칙을 공유하며, 별도의 특수 최적화나 전용 스키마가 필수는 아니다. 우선 색인 가능 여부, 본문에 드러나는 정확한 기능 설명, 내부 링크를 정리한다. 이 원칙을 모든 AI 서비스의 정책으로 일반화하지 않고 다른 서비스는 실행 시 공식 문서를 확인한다. [Google AI 검색 안내](https://developers.google.com/search/docs/appearance/ai-features)

검색 제목은 페이지 내용을 구체적이고 간결하게 설명한다. 구조화 데이터는 본문과 일치하게 작성하며 특수 검색 표시를 보장하지 않는다. [검색 제목 안내](https://developers.google.com/search/docs/appearance/title-link), [앱 구조화 데이터 안내](https://developers.google.com/search/docs/appearance/structured-data/software-app)
